# متابعة المشاريع واللجان غير المالية

إضافة لـ ERPNext/Frappe 16 توسّع Project وTask. **ثُبتت الإضافة على lib.ly بتاريخ 2026-09-15 بعد موافقة المستخدم الصريحة.** نجحت تجربة تكامل فعلية بمعاملة أُعيدت بالكامل: إنشاء مشروع دون ميزانية، إسناد مهمة، صلاحيات العضو والرئيس، التمديد، الإعادة والمراجعة، وصول الإنجاز إلى 100% دون إقفال تلقائي، ثم اعتماد إقفال المشروع. لا توجد مشاريع اختبار متبقية.

## النطاق المثبت

- إضافة نمط «متابعة غير مالية» إلى Project، مع نوع العمل ورئيس اللجنة وجدول الأعضاء واختصاصاتهم. النمط الافتراضي للمشاريع هو «مالي»؛ لا تُحوّل المشاريع القديمة تلقائيًا.
- إضافة المسؤول المباشر والاختصاص والموعد الأصلي ونتيجة العمل والمرفق والتعثر وقرارات المراجعة والتمديد إلى Task.
- ضوابط الخادم على المشاريع المصنفة متابعة غير مالية: لا إقفال تلقائي عند 100%، ولا اعتماد مهمة إلا بعد تقديمها للمراجعة، ولا تغيير لموعدها إلا بطلب تمديد واعتماد، ولا حذف لمهامها أو تعديل لقرارات الإقفال.
- رئيس اللجنة أو Administrator يملك اتخاذ قرارات المراجعة والإلغاء والإقفال. أعضاء اللجنة يقدّمون نتيجة مهامهم ويطلبون التمديد. يمكن للرئيس تقديم المهمة للمراجعة أيضًا.
- منح مشاركات محددة لأعضاء المشروع والمسؤولين عن المهام دون إضافة أدوار عامة إلى حساباتهم. قوائم المشاريع والمهام تراعي العضوية؛ System Manager وProjects Manager يستطيعان الاطلاع، والاعتماد مقيد بالرئيس أو Administrator.
- تفعيل Version عبر track_changes على Project وTask لتوثيق التغييرات، بما فيها حقول التمديد والاعتماد.
- منع الربط المالي للمشروع غير المالي عبر Budget وSales/Purchase Order وSales/Purchase Invoice وJournal Entry وPayment Entry وExpense Claim وStock Entry وTimesheet. يُرفض التحويل إذا وجدت ارتباطات مالية أو مبالغ قائمة، بما فيها السجلات القديمة، بدل إخفائها.
- تذكيرات داخل النظام قبل الموعد بيوم، وتصعيد التأخر للرئيس، دون بريد إلكتروني. تعتمد على تشغيل مجدول Frappe. يُرسل تنبيه واحد لكل موعد/مرحلة/مستخدم لتجنب التكرار.
- صفحة `/app/project-followup` تعرض المشاريع المتاحة للمستخدم، ونسبة المهام المعتمدة ومهامها المتأخرة. الحد الحالي للعرض 200 مشروع.

## دورة العمل

1. افتح Project واختر «متابعة غير مالية»، وحدد رئيس اللجنة ونوع العمل وموعد المشروع والأعضاء واختصاصاتهم.
2. استخدم «إضافة مهمة» لتحديد المسؤول من الأعضاء، والاختصاص والموعد النهائي.
3. المسؤول يختار «بدء التنفيذ»، ثم يرفق النتيجة ويختار «تقديم للمراجعة».
4. الرئيس يختار «اعتماد الإنجاز وإقفال المهمة» أو «إعادة للتنفيذ» مع السبب.
5. التمديد يحتفظ بالموعد الأصلي، ولا يغيّر الموعد الحالي قبل اعتماد الرئيس. التمديد بعد نهاية المشروع يتطلب تعديل نهاية المشروع أولًا وفق تحقق ERPNext الأساسي.
6. عند انتهاء العمل، يختار الرئيس «مراجعة وإقفال المشروع» ويحدد مكتمل/متوقف/ملغى والتقرير الختامي وتاريخ الانتهاء الفعلي إن عُرف. تاريخ تسجيل الإقفال يحفظ تلقائيًا بصورة مستقلة.

المهام الملغاة لا تُحسب كمنجزة؛ المشروع الذي يحتوي على مهام ملغاة لا يقفل باعتباره مكتملًا. يجب توثيق إلغاء الأعمال غير المنجزة قبل إقفال المشروع كمتوقف أو ملغى. المشروع القديم دون مهام يمكن إقفاله بقرار وتقرير ختامي. المهام القديمة المكتملة دون مراجعة مسجلة تحتاج تقديمًا للمراجعة واعتمادًا عند استخدام المسار الجديد.

## حدود النسخة

- الإقفال نهائي في الواجهة؛ لا توجد إعادة فتح لقرار إقفال معتمد في هذه النسخة.
- المهام التنفيذية مستقلة؛ المجموعات والقوالب غير مدعومة في المسار الإداري الجديد. المهام المالية تحتفظ بسلوك ERPNext.
- هذه مراجعة إدارية مسجلة بالحساب والتاريخ وليست توقيعًا رقميًا بشهادة. لم يُربط إقفال المشاريع بتطبيق manager_signature.
- الحماية على مستوى دورة مستندات التطبيق؛ SQL المباشر أو كود يتجاوز التحقق لا يشمله هذا الضمان.
- أُجري اختبار تكامل على الموقع الفعلي مع rollback، وفُحصت ملفات الواجهة وتحميل الصفحة. لم تُجرَ تجربة نقر داخل المتصفح. مجدول النظام مفعّل ومهمة التنبيه اليومية مسجلة وغير متوقفة.

## التحقق المنفذ

نجحت 15 حالة وحدة تستخدم بديل Frappe، وتغطي صلاحيات الموظف والرئيس، شرط نتيجة العمل، الإعادة/الاعتماد، التمديد، منع إقفال المشروع قبل مراجعة مهامه، عدم احتساب الملغى مكتملًا، عدم الإقفال التلقائي، منع الارتباط المالي للمشروع غير المالي مع تمرير المشروع المالي، وتطبيع التواريخ القادمة من المتصفح.

```sh
PYTHONPATH=apps/project_followup python3 -m unittest discover -s apps/project_followup/tests -v
python3 -m compileall -q apps/project_followup/project_followup
node --check apps/project_followup/project_followup/public/js/task.js
node --check apps/project_followup/project_followup/public/js/project.js
node --check apps/project_followup/project_followup/project_followup/page/project_followup/project_followup.js
```
